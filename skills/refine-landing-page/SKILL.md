# Refine landing page

Improve an existing landing page against the notes that hold its market test: explore the page, the notes and the mocks, report what the notes imply and the page lacks, interview, edit in place, and, when the test is over, record its result and the decision beside the page. Leave the result uncommitted. It never creates the page; a repo with no `docs/landing-page/index.html` is `jodysalt:add-landing-page`'s. No branch gate: the page is a product artefact, not a spec.

## Scope

$ARGUMENTS

If given, one of three things. One or more section names, matched case-insensitively against the page's section ids – `headline`, `hero`, `benefits`, `price`, `cta`, `faq`, `terms` – and `README.md`'s `##` headings – `hypothesis`, `metric`, `threshold`, `window`, `call to action`; the findings and the interview cover only those sections. A mock slug, with or without its `mock-` prefix, matching `mocks/mock-{slug}.html`; the findings and the interview cover only that mock. Or `result`, which runs the findings and then step 6. If empty, the whole page. If a name matches nothing, list the names and ask.

## Steps

1. **Root and guard.** The root is `git rev-parse --show-toplevel`, else the working directory. If `docs/landing-page/index.html` is missing under it, stop and point at `jodysalt:add-landing-page`; this skill improves a page, it never creates one, and nothing is written. Read `docs/glossary.md` when it exists, a missing or template-only file counting as an empty glossary, and use each defined term in its defined sense in the edits and the report, never redefining one in passing; a term the glossary lacks is used as the input uses it.
2. **Explore before asking.** Read `docs/landing-page/index.html`, `docs/landing-page/README.md` when present, `docs/landing-page/mocks/index.html`, `docs/landing-page/mocks/mock.css` and every `docs/landing-page/mocks/mock-*.html` when present, and `ls docs/landing-page/mock-*.png` for the screenshots on disk. Take today's date from `date +%F`. Recommended answers come from these.
3. **Report findings before editing anything.** Each finding is named by the section, file or slug it is about:
   - Each of the seven section ids the page lacks – `#headline`, `#hero`, `#benefits`, `#price`, `#cta`, `#faq`, `#terms` – and `README.md` missing, or each of its five `##` headings – `Hypothesis`, `Metric`, `Threshold`, `Window`, `Call to action` – missing or empty. The two the page mirrors are cross-checked against it: `## Call to action` naming a link that differs from a filled `href` on `#cta`'s `<a>` (an empty one is the next finding, reported once), and `## Hypothesis` claiming a benefit no `<h3>` in `#benefits` names.
   - `#cta`'s `<a>` with `href=""` or no `href`.
   - `#hero` with no `<img>`, and each benefit – an `<h3>` in `#benefits` – with no `<img>` before the next `<h3>` or the section's end.
   - Each `<img src>` on the page or in `mocks/index.html` with no file on disk at `docs/landing-page/mock-{slug}.png`; and each `mocks/mock-{slug}.html` with no row in `mocks/index.html` or no `<img>` on the page pointing at its screenshot.
   - `## Result` or `## Decision` still holding its `TODO:` prompt once today's date, from `date +%F` in step 2, is past the end date in `## Window`, the end date read as the last `YYYY-MM-DD` in that section, else the last date it can read; a window whose end date cannot be read is its own finding.
   - A `TODO:` anywhere in the page, `README.md` or a mock, the `## Result` and `## Decision` prompts aside: those are the finding above once the window has ended and the right state until then.

   With `result`, the findings are reported and step 6 follows, the interview covering only the result.
4. **Interview.** Invoke the `grill-me` skill from this plugin (`jodysalt:grill-me`) with the subject "the landing page at `docs/landing-page/index.html` and its market test at `docs/landing-page/README.md`". Give it this framing:
   - Seed the decision tree with the findings from step 3, then add the decisions the page makes without saying so: a price with no terms, a FAQ that skips an objection the terms imply, a headline that promises what no benefit backs.
   - The page, the notes, the mocks and the screenshots from step 2 count as explorable; a question they answer is never asked, and each recommended answer cites what it came from.
   - Only an answer the user agrees to lands. A run where the user declines every question leaves every file under `docs/landing-page/` byte for byte unchanged.
   - Edit `docs/landing-page/index.html` and `docs/landing-page/README.md` as answers land, keeping the page's shape as `add-landing-page` fixed it: the section ids and their order (`#headline`, `#hero`, `#benefits`, `#price`, `#cta`, `#faq`, `#terms`), inline CSS only, no `<link>` and no `<script>` but a user-supplied analytics snippet, every `<img src>` a bare `mock-{slug}.png` beside the page, and `og:title`, `og:description` and `og:image` following the headline, the subhead and the hero when those change. A deferred answer becomes a `TODO:` marker in its section.
   - When an answer needs a screen the page does not have, or changes what a screen shows, ask for that screen as `add-landing-page` does: its short name, whose kebab-case form is its `{slug}`; what it shows and in what state (a filled dashboard, an empty first run, a confirmation after the action); which benefit it illustrates; and whether it is a desktop or a phone screen (desktop recommended, screenshot `1280,800`; phone `390,844`). Run step 5 for that one screen as the answer lands, adding or correcting the page's `<img src="mock-{slug}.png" alt="…">` – after that benefit's `<p>`, or inside `#hero` when the screen is the hero. When the finding is a screenshot missing for a mock that exists, ask only its size and run step 5 for that screen, which leaves the mock untouched and takes the picture.
   - When the user says the test is over, run step 6.
   - `docs/glossary.md` is read, never written.
5. **Write the mocks.** When the answer rewrites a screen whose `mocks/mock-{slug}.html` exists, that one file is removed first so the step below writes it afresh, and its `<li>` in `mocks/index.html` is rewritten when its name or description changed; every other mock, `mock.css` and `mocks/index.html` beyond that row keep the never-overwrite rule below, and a re-taken screenshot overwrites the `.png`, which is what the command does. For each screen, in order, with its slug, name, description, state and size (`{w},{h}`), write the mock that fakes it and take its screenshot, one screen finished before the next:
   - Write `docs/landing-page/mocks/mock-{slug}.html`, creating the folder: one self-contained page faking that screen in that state – `<!doctype html>`, `<html lang="…">` in the page's language, `<meta charset="utf-8">`, the viewport meta `width=device-width, initial-scale=1`, a `<title>` holding the screen's name, `<link rel="stylesheet" href="mock.css">`, no `<script>`, realistic placeholder content in the product's own words, and the whole screen inside the window at the chosen size so the screenshot is the screen and nothing else. A screen whose description is a `TODO:` holds that sentence in place of the content, and the mock is still written. When `mock-{slug}.html` already exists it is left untouched, byte for byte, and the run says so; the row and the screenshot still happen.
   - With the first mock, when they are missing: `docs/landing-page/mocks/mock.css` – `body` at `margin: 0`, the font stack `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`, a `min-height: 100vh` frame, a neutral palette and a handful of classes every mock shares (a top bar, a card, a button, a table), a short file the mocks lean on rather than restyle; and `docs/landing-page/mocks/index.html` – `<!doctype html>`, `<html lang="…">` in the page's language, `<meta charset="utf-8">`, `<title>Mocks</title>`, the same `<link rel="stylesheet" href="mock.css">`, an `<h1>`, and one `<ul>`. Both are left untouched when present.
   - Append `<li><a href="mock-{slug}.html">{screen name}</a> <img src="../mock-{slug}.png" alt="{screen description}"></li>` to that `<ul>` unless the index already holds a row for `mock-{slug}.html`.
   - Find a browser: `command -v google-chrome chrome chromium`, taking the first hit; none, and on macOS `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` exists, take that. With a browser, run from the root `"{chrome}" --headless --screenshot=docs/landing-page/mock-{slug}.png --window-size={w},{h} docs/landing-page/mocks/mock-{slug}.html`, `{w},{h}` the screen's size. Without one, or when the command exits non-zero or leaves no file, print that one command with `google-chrome` as the binary for the user to run and carry on; the mock, its row and the page that points at `mock-{slug}.png` are written either way, and nothing is installed.
6. **Record the result.** With `result`, or when the user says the test is over, ask through the same interview for the metric's value at the window's end – no recommended answer, the number is the user's – then write `## Result` in `docs/landing-page/README.md` as one line: the metric, its value, the threshold and whether it was met. Then ask the decision, the three options the prompt's own – `build`, `change the offer`, `stop` – recommended `build` when the threshold was met, `stop` when it was not, and `change the offer` when the interview finds the page misrepresented the idea rather than the idea failing; write `## Decision` as that one word or phrase and a sentence of why. A `## Result` already filled is shown as it stands and rewritten only when the answer says so.
7. **Report.** The findings resolved and those left open; the files edited (`docs/landing-page/index.html`, `docs/landing-page/README.md`); each mock written or rewritten as `mocks/mock-{slug}.html`, `mocks/mock.css` and `mocks/index.html` when this run created them, and each screenshot taken at `docs/landing-page/mock-{slug}.png`. For each screenshot not taken, the one command to run – `google-chrome --headless --screenshot=docs/landing-page/mock-{slug}.png --window-size={w},{h} docs/landing-page/mocks/mock-{slug}.html` – saying the page already points at `mock-{slug}.png` and, once, that a macOS user substitutes `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` for `google-chrome`. When the result was recorded, say that `## Result` and `## Decision` now hold it and that `jodysalt:refine-vision` cites them. Say that everything is uncommitted and suggest `jodysalt:commit` – a `feat:` commit when the page or a mock changed, a `docs:` commit when only the notes did.

## Rules

- Never creates `docs/landing-page/index.html`; a missing page stops the run before anything is written.
- Writes nothing outside `docs/landing-page/`.
- Never edits `.github/workflows/landing-page.yml`.
- Rewrites only the mock the answer names; `mock.css`, `mocks/index.html` beyond that mock's row, and every other mock are never overwritten.
- The screenshot command is the only program run beyond `git` and `date`, and nothing is installed.
- Never invents copy, a result or a decision; asks, or leaves a `TODO:` marker.
- Never pushes, never commits, never enables GitHub Pages, never picks a payment, form or analytics provider.
- Reads `docs/glossary.md` and never writes it.
