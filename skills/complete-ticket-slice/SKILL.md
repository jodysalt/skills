# Complete ticket slice

Implement one thin, end-to-end slice of an open ticket: read the ticket's acceptance criteria and what its sub-tickets already cover, pick the next slice, draft it as a `{slug}--{sub}` sub-ticket through `jodysalt:add-ticket`, write its tasks and run the loop on them. Each slice gets its own worktree at `.claude/worktrees/{slug}--{sub}` on a branch forked from the parent's branch `{slug}`, is squashed to one commit with `jodysalt:squash-commits` against the parent, and fast-forwards into the parent, so the parent branch reads as one commit per slice until `jodysalt:wrap-up-worktree` squashes it onto the base as it does any ticket. The worktree, the merge and the removal are this skill's own git commands: `jodysalt:add-worktree` cannot take a start point, `jodysalt:merge-worktree` only merges into the base, and `jodysalt:remove-worktree` deletes a branch from the main checkout, where a slice is never merged. One slice per call; `jodysalt:complete-ticket` calls it again until the ticket's criteria are met.

## Ticket

$ARGUMENTS

The parent: a slug, a `docs/tickets/open/{slug}` directory, or any file inside it, reduced to the slug. Any open ticket will do, a sub-ticket included; its slices are then `{slug}--{sub}--{leaf}`. If empty: the open ticket named by the current branch, else the only directory in `docs/tickets/open/`, else `ls docs/tickets/open/` and ask. Stop if the branch or the argument names a closed ticket.

## Steps

1. **Guard.** The main checkout is the first path in `git worktree list`. `<main checkout>/docs/tickets/open/{slug}/index.md` must exist; otherwise stop, change nothing, and say to land the planning branch that holds the ticket with `jodysalt:wrap-up-worktree` first. `ls -d <main checkout>/.claude/worktrees/{slug}--* 2>/dev/null` must print nothing; otherwise a slice is in progress or stopped: stop and name it, saying to finish it with `jodysalt:complete-tasks` in that worktree or clear it with `jodysalt:remove-worktree`.
2. **Worktree.** If `git rev-parse --show-toplevel` already equals `<main checkout>/.claude/worktrees/{slug}`, skip this step. Else if that path is registered in `git worktree list`, invoke `jodysalt:enter-worktree {slug}`. Else invoke `jodysalt:exit-worktree` when the session is inside another worktree, then `jodysalt:add-worktree {slug}` (declining its offer to enter), then `jodysalt:enter-worktree {slug}`. `git status --porcelain` must be empty here; otherwise stop and say the parent worktree is dirty.
3. **Judge.** Read the parent's `# Acceptance criteria`, the `index.md` of every sub-ticket `docs/tickets/*/{slug}--*/` with the `findings.md` of each spike among them, the parent's `tasks.md` when it has one, and the repo as it is. Mark each criterion met or unmet with a line of evidence. Every criterion met: report as step 10 says, with `done` as the last line, and stop; nothing is drafted. Otherwise pick the slice: the thinnest end-to-end piece, every layer the criterion needs and nothing more, that moves the unmet criteria most and that no sub-ticket or parent task already covers. Its type is any `add-ticket` type; a spike, as the question to answer, when it cannot tell which slice moves them or the ticket needs facts the repo does not hold. Give it a kebab-case `{sub}` naming the what.
4. **Draft the slice.** Spawn one sub-agent with the Agent tool (`general-purpose`, run synchronously) that invokes `jodysalt:add-ticket {slug}--{sub}` with the pick and its reason, framed as unattended: no person reads its conversation; where `add-ticket` interviews, the parent's `index.md` answers first, the recommended answer stands for the trivial many, and the vital few come back in its report, each with options and a recommendation; take no offer of another skill, the planning-session offer included, so the sub-ticket is drafted on the parent branch. Answer each returned question from the parent's `index.md`; when it is silent, ask the driver one question at a time with the recommendation, which an unattended caller resolves by `grill-me`'s rule. Send the answers to the same sub-agent with `SendMessage` so its context stays intact, and wait for it to finish. Then `jodysalt:commit` staging only `docs/tickets/open/{slug}--{sub}` with the subject `docs: drafted the {slug}--{sub} slice`, so the parent branch holds the slice's record before any code exists.
5. **Fork.** From the parent worktree, `git worktree add <main checkout>/.claude/worktrees/{slug}--{sub} -b {slug}--{sub} {slug}`, the absolute path so nothing nests inside the parent worktree, then `jodysalt:enter-worktree {slug}--{sub}`.
6. **Tasks.** Invoke `jodysalt:add-tasks {slug}--{sub}`, then `jodysalt:commit` staging only that sub-ticket's `tasks.md` (and a spike's `findings.md` when `add-tasks` created it) with the subject `docs: added tasks for {slug}--{sub}`, so the loop starts on a clean tree.
7. **Loop.** Invoke `jodysalt:complete-tasks {slug}--{sub}`. On its first failed task, stop with its report and leave the slice worktree and the session in place; step 1 names it on the next call.
8. **Close the slice.** Invoke `jodysalt:close-ticket {slug}--{sub}`, then `jodysalt:commit` staging explicitly `docs/tickets/open/{slug}--{sub}`, `docs/tickets/closed/{slug}--{sub}` and every file `close-ticket` reported rewriting, with the subject `docs: closed the {slug}--{sub} ticket`. Never close the parent.
9. **Land on the parent.** Invoke `jodysalt:squash-commits {slug}`, the parent branch as its base, folding the tasks, the work and the close into one commit. Then `jodysalt:enter-worktree {slug}` and, from the parent worktree, `git merge --ff-only {slug}--{sub}`; if git refuses, report its message and stop, keeping the slice worktree and branch. Then `git worktree remove <main checkout>/.claude/worktrees/{slug}--{sub}` and `git branch -d {slug}--{sub}`, which succeeds here because the parent's `HEAD` now holds the slice.
10. **Report.** Each criterion from step 3 with its verdict and evidence; the loop's summary and every check it left for a person; `git log -1 --stat` on the parent branch, naming it; and the last line, `done` when step 3 stopped there, otherwise `{slug}--{sub}` followed by the criteria still unmet, so `jodysalt:complete-ticket` reads one line. The session ends in the parent worktree, its tree clean, nothing landed on the base.

## Rules

- One slice per call, and never a slice of the slice it is working on; the next call's judge decides what the slice left unmet.
- Only orchestrates: never implements a task, edits any `tasks.md` itself, or spawns workers itself; `complete-tasks` does.
- Never closes the parent, never lands anything on the base, never wraps up, never pushes.
- Its own git is confined to what no sibling can do: a worktree forked from the parent branch, a fast-forward into the parent branch, and that worktree's removal with its merged branch. Never `--no-ff`, a rebase, a reset or a force.
