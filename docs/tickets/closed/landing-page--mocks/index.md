# Goal
`/jodysalt:add-landing-page` also leaves the mocks: the interview gains a **Screens** branch between Offer and Test, one question per product screen the copy shows, and for each screen the skill writes `docs/landing-page/mocks/mock-{slug}.html` against a shared `mocks/mock.css`, adds its row to `mocks/index.html`, and takes a screenshot to `docs/landing-page/mock-{slug}.png` with headless Chrome when one is found, else prints the one command that would, so the page's hero and benefits point at screenshots the workflow ships while the mocks themselves stay unpublished. A user with an idea and an empty repo gets a landing page whose copy is backed by pictures of the product, and the mocks outlive the test as the design reference the first tickets are drafted against.

# Scope
In, all in `skills/add-landing-page/SKILL.md` and its README row:
- **Description and paragraph.** The description's first sentence gains the mocks: it interviews for the offer, the screens and the market test, and writes the page with its hypothesis beside it, the mocks of the screens its copy shows and their screenshots, and the workflow when missing. The README row (`README.md`, the `add-landing-page` row) is that sentence. The title paragraph names the mocks among what is left uncommitted.
- **Step 2, a Screens branch** between Offer and Test, so the interview runs Offer, Screens, Test, Analytics. The branch opens by asking how many screens the copy shows, recommended one per benefit the Offer branch settled, at least one; then one question per screen: a short name (its kebab-case form is the `{slug}`), what the screen shows and in what state (a filled dashboard, an empty first run, a confirmation after the action), which benefit it illustrates when it does, and whether it is a desktop or a phone screen (desktop recommended, screenshot `1280,800`; phone `390,844`). The first screen is the hero and the question says so; its slug is the `{hero-slug}` the page uses. A deferred answer leaves the screen a `TODO:` sentence in its mock and the mock is still written.
- **Step 3, the page**, changed in three places: `<figure id="hero">` holds `<img src="mock-{hero-slug}.png" alt="…">`, the `alt` the hero screen's one-line description, in place of the comment; each benefit a screen illustrates gets `<img src="mock-{slug}.png" alt="…">` after its `<p>`, no `<img>` for a benefit with no screen; and `<meta property="og:image">` is written as `https://{user}.github.io/{repo}/mock-{hero-slug}.png` under the same condition as `og:url` – no `og:url`, no `og:image`. The "no `<img>`" clause becomes: no `<img>` but the screenshots, whose `src` is a bare `mock-{slug}.png` beside the page. The page references each screenshot whether or not Chrome took it; a missing file is `refine-landing-page`'s finding.
- **A new step, Write the mocks**, after the notes and before the workflow (the workflow becomes step 6 and the report step 7), written so `refine-landing-page` can copy it verbatim: it speaks of "each screen" and "the screen's slug, description, state and size", never of "the interview" or "step 2". For each screen, in interview order:
  - Write `docs/landing-page/mocks/mock-{slug}.html`, creating the folder: one self-contained page faking that screen in that state – `<!doctype html>`, `lang`, viewport meta, `<title>` the screen's name, `<link rel="stylesheet" href="mock.css">`, no `<script>`, realistic placeholder content in the product's own words, the whole screen inside the window at the chosen size so the screenshot is the screen and nothing else. When `mock-{slug}.html` already exists it is left untouched and the run says so; the row and the screenshot still happen.
  - With the first mock, when they are missing: `docs/landing-page/mocks/mock.css` – `body` at `margin: 0`, the page's font stack `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`, a `min-height: 100vh` frame, a neutral palette and a handful of classes every mock shares (a top bar, a card, a button, a table), a short file the mocks lean on rather than restyle; and `docs/landing-page/mocks/index.html` – `<!doctype html>`, `<title>Mocks</title>`, the same `<link rel="stylesheet" href="mock.css">`, an `<h1>`, and one `<ul>`. Both are left untouched when present.
  - Append `<li><a href="mock-{slug}.html">{screen name}</a> <img src="../mock-{slug}.png" alt="{screen description}"></li>` to that `<ul>` unless the index already holds a row for `mock-{slug}.html`.
  - Find a browser: `command -v google-chrome chrome chromium`, taking the first hit; none, and on macOS `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome` exists, take that. With a browser, run from the root `"{chrome}" --headless --screenshot=docs/landing-page/mock-{slug}.png --window-size={w},{h} docs/landing-page/mocks/mock-{slug}.html`, `{w},{h}` the screen's size. Without one, or when the command exits non-zero or leaves no file, print that one command with `google-chrome` as the binary for the user to run and carry on; the mock, its row and the page are written either way. Nothing is installed.
- **Step 7, the report**, adds the mocks written (each `mocks/mock-{slug}.html`), `mocks/mock.css` and `mocks/index.html` when created, each screenshot taken at `docs/landing-page/mock-{slug}.png`, and, for each not taken, the one command to run, saying the page already points at that file.
- **Rules**: never overwrites an existing mock, `mock.css` or `mocks/index.html`; the screenshot command is the only program run beyond `git`, and nothing is installed; the "writes nothing outside" rule stands as written since the mocks and screenshots sit under `docs/landing-page/`.
